# Screenshots

The images in `docs/images/` were taken from the build produced by this
repository, on Linux x86-64, under a virtual X server. They are reproducible:
see `scripts/screenshots/capture.sh`.

## What was not captured, and why

- **systemd service** — installing the unit would add a system service to the
  build host. The unit file is in `packaging/systemd/` and is covered by
  `docs/DEPLOY.md`.

## How they were taken

- Capture screenshots needed raw sockets. The GUI was run inside a user and
  network namespace (`unshare -rn`) so the process had `CAP_NET_RAW` without
  root, with loopback traffic generated by a ping loop. Every address in those
  images is `127.0.0.1`, so no real network appears.
- The container image was built with Podman 5.8 on the same host. Docker Hub is
  not reachable here, so the base images were fetched through a registry mirror
  while building; the committed Dockerfile keeps the canonical
  `docker.io/library/eclipse-temurin` names.
- Virtual display: `Xvfb` with `xfwm4` as window manager so windows have real
  decorations. Window screenshots use `import -window <id>`; dialogs are
  captured individually. Terminal shots run a small script that prints the
  command and its output, then crop a root capture.
- Framing: 1 px `#d0d7de` border plus 12 px `#f6f8fa` padding, metadata stripped,
  PNG compression level 9. Window shots are scaled to 1280 px wide, dialogs to
  900, terminals to 1100.
- Nothing personal appears: paths are `/tmp/cicfm/...`, the prompt is `$ `, the
  interface is `lo`, and all addresses are loopback.
